## The lesson this branch actually taught

Every single one of the four implementation tasks shipped at least one bug of the
same shape: a placeholder rendered where real data belongs, one field preferred so
another silently vanished, or a placeholder counted as a real thing.

Four separate tests pinned answers the real system would never produce. One assumed
temporary files land in `/tmp` when macOS puts them under `/var/folders`. Another
returned a ledger entry with no project key while typed as having one, which
defeated the very fix it was meant to guard.

Not one of those was caught by the suite going red. Every one was caught by a review
or by a worker re-auditing its own tests.

Green was not evidence on this branch. The useful question turned out to be not
"does the test pass" but "is the value this test asserts one the real system can
actually produce".

## What the whole-branch review found

Verdict Blocked, on six findings, all now closed in `734c81c`:

1. Critical. `text-maestro-onAccent` was not a real Tailwind class, because the token
   is `on-accent`. Tailwind generated no rule at all, so two accent-filled buttons
   silently fell back to body text and failed contrast in both themes. The guard test
   covered one of three sites. It now walks every ported surface and fails if the
   camelCase spelling ever generates a rule again.
2. A test fixture returned a ledger entry with no project key while typed as having
   one. The count logic also discriminated on `=== null`, so an entry holding
   undefined was counted as a real project.
3. The session setup panel printed the picker's placeholder word "Current" as the
   branch a launch would actually use.
4. The screen title was a real heading element on only two of six ported screens.
5. About 516 lines of unreachable toolbar shell, a dead prop that had drifted from
   its live twin, and dead CSS.
6. The Inbox was called four different things across rail, title and close control.

## The failure mode this project keeps hitting

Two workers died mid-task and left no report. The first left a reviewer's findings
unrecorded. The second left 23 modified files uncommitted with a fix round half
landed and no way to tell, from the outside, whether it had finished.

What made that recoverable was the handoff naming the exact commit the tree should
be measured against, and saying plainly that the uncommitted work was real and must
be read before being discarded. What would have made it cheap is a worker that
commits as it goes rather than at the end.
