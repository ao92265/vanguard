## Approach

Port the supplied layouts into the existing React application, keeping Zustand
stores, Tauri commands and real action handlers. Do not ship the design runtime or
replace the live application with a static demo. `support.js` is the export's
template/compiler runtime: it loads React from a CDN and evaluates design logic.
It is a reference-preview dependency, not an application dependency.

Alternatives considered:

- Embed the exported prototype: closest immediate demo, but fake data and inert
  action labels make it unsuitable as the working application.
- Port the design onto existing capabilities (recommended): match layout and
  interaction structure while retaining working agents and honest state.
- Implement every implied new backend capability too: separate host-management,
  remote-launch, audit and messaging work; not a visual port.

## Visual contract

Reference content viewport: 1440 × 900, without the surrounding canvas.
Match both supplied themes, with dark as the initial comparison target.

- One combined navigation/project strip: 58px collapsed, 232px expanded, 160ms
  width transition. Hover and keyboard focus reveal labels; provide a pin control
  for touch and persistent expansion. Reduced-motion settings disable animation.
- Navigation order: Inbox, Board, Orchestrator, Pulse, Factory, Ledger, New session,
  Terminals; projects below, More at the bottom.
- Right utility dock: 68px, with Git, AI, Processes, Notes, Memory and Second Brain.
  Existing functionality behind More and the dock remains reachable.
- Footer: 48px, carrying real session information, quick-open, watchdog and usage.
  Preserve native window dragging/controls in a minimal platform-safe region;
  do not draw fake macOS traffic lights.
- Dark palette: background #0d0d10, surface #121316, card #18191c, border #26262c,
  text #e8e8ec, muted #9494a0, accent #828fff. Light palette comes from the export.
- Inter for interface text; JetBrains Mono for labels, numbers and metadata.
  Acquire and bundle licensed font assets without a runtime CDN dependency.
  Missing exact fonts block a pixel-perfect claim; do not silently substitute.
- Preserve the export's spacing, sizes, radii and status edges. Content may differ
  because the app uses real data; compare geometry with controlled test fixtures.

## Explicit backend boundary

The design contains sample assertions that must not be copied as facts:

- An image destination is not verified evidence of where the terminal executes.
  Preserve this distinction; selecting an attachment target must not imply remote
  agent launch, host reachability or remote worktree management.
- Production staging uses random temporary directories, not the sample
  `/home/ao/.vanguard/images/` directory. Display returned paths only.
- Current retention is 24 hours with cleanup on session close and retries while
  the app runs, not cleanup after each turn. Keep the actual lifecycle and copy.
- Do not show successful host-key, ownership or delivery checks before real results.
- The sample “Send to Telegram too” is not permission to invent an outbound
  messaging channel or choose a chat. Do not ship it as an inert working-looking
  button; omit it from this port unless an existing supported route is established.
- No new remote host manager, SSH daemon, turn-end cleanup protocol, outbound
  Telegram service or persistent audit schema in this implementation.

The visual structure is the target; correctness-related copy and unsupported
sample controls are explicit deviations requiring acceptance of this boundary.
