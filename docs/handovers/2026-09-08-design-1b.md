### The four resolves-to defects: DONE

Four defects sat in the session setup panel's resolves-to rows, all pre-existing
mechanisms, all the same shape, none introduced by this branch: the branch list was
never cleared on a repository switch, auto mode reuses whatever managed worktree it
finds, a remote-only ref displayed with a prefix the launch strips, and the git flag
lagged one poll behind the selection.

They are fixed together, in two places rather than four patches:

- `refreshBranches` (TerminalGrid) drops the previous repository's branch list the
  moment the selection changes, and a poll for an abandoned repository can no longer
  repaint over the answer for the one actually selected. `isGitRepo` is deliberately
  left alone on a switch: replacing a claim about the previous repository with an
  unchecked claim about the new one swaps one wrong answer for another. Readers are
  told the answers are in flight by `isLoadingBranches` instead.
- `branchResolvesTo` (PreLaunchCard) decides the row from the conditions
  `launchSlotInner` actually reads. It says nothing while a poll is in flight, names
  the LOCAL branch a remote-only choice lands on (mirroring
  `resolve_local_branch_name`), and refuses to name a branch in auto mode with no
  explicit choice, because the backend returns the first managed worktree's branch
  rather than HEAD.

Seven tests, in `PreLaunchCard.test.tsx` and the new
`TerminalGrid.branchPoll.test.tsx`. Four cover the defects and three guard the fix
from over-firing: a local branch containing a slash is not stripped, `project` and
`new` modes still name the current branch because their launch paths really do use
it, and an ordinary refresh of the same repository keeps its list rather than
blinking the picker empty. Every one was proven red first and goes red again when
its arm of the fix is mutated away.

Still true and still not fixed: `slot.branch` survives a repository switch, so an
explicit choice made in one repository is still named after moving to another. That
is a fifth mechanism in the parent, not in these two files, and nobody has asked
for it.
